# Phase 5: 可观测层执行方案
**目标**：在治理逻辑闭环的内核之上，正式引入可观测性一等公民。通过 `tracing` 实现全链路上下文穿透与关联，通过 `metrics` 实现核心运行时指标暴露。严格遵循低开销与无侵入原则，不破坏现有异步调度语义。
---
## 1. 依赖扩展与架构边界
**原则**：内核仅依赖 `tracing` 和 `metrics` 的**门面 (facade)** crate，不绑定特定后端。后端组装由应用层在 `main` 中完成，保持内核的轻量与中立。测试时引入 `tracing-subscriber` 提供基础验证能力。
```toml
[dependencies]
tracing = "0.1"
metrics = "0.22"
[dev-dependencies]
tracing-subscriber = "0.3"
```
---
## 2. Tracing 上下文穿透与关联
**设计原理**：由于消息跨 `tokio::spawn` 传递，Tracing 原生 Context 无法自动流动。采用 `trace_id` 显式关联策略：在 `dispatch` 入口建立根 Span，在内层循环通过 `info_span!` 建立处理 Span，实现日志系统（如 ELK/Loki）中的全链路串联。
### 2.1 路由入口埋点 (`kernel/mod.rs`)
在 `dispatch` 入口建立 Span，使得路由阶段的日志与错误自动归属到该上下文。
```rust
use tracing::{info_span, Instrument};
use metrics::counter;
impl Kernel {
    async fn dispatch(&self, target: CapabilityId, env: Envelope) -> KernelResult<()> {
        let ext_id_str = target.to_string();
        
        // 建立入口 Span，后续逻辑自动关联
        let span = info_span!(
            "kernel_dispatch",
            trace_id = %env.trace_id,
            correlation_id = %env.correlation_id,
            target = %ext_id_str
        );
        let _enter = span.enter();
        if self.monitor.is_stopping() {
            self.dlq.sink(env, KernelError::SystemShuttingDown).await;
            counter!("referee_dispatch_total", "ext_id" => ext_id_str, "result" => "shutting_down").increment(1);
            return Err(KernelError::SystemShuttingDown);
        }
        if self.monitor.is_crashed(&target) {
            self.dlq.sink(env, KernelError::ExtensionCrashed).await;
            counter!("referee_dispatch_total", "ext_id" => ext_id_str, "result" => "crashed").increment(1);
            return Err(KernelError::ExtensionCrashed);
        }
        
        match self.router.try_send(target, env) {
            Ok(()) => {
                counter!("referee_dispatch_total", "ext_id" => ext_id_str, "result" => "ok").increment(1);
                Ok(())
            }
            Err(TrySendError::Full(env)) => {
                self.dlq.sink(env, KernelError::ResourceExhausted).await;
                counter!("referee_dispatch_total", "ext_id" => ext_id_str, "result" => "full").increment(1);
                Err(KernelError::ResourceExhausted)
            }
            Err(TrySendError::Closed(env)) => {
                self.dlq.sink(env, KernelError::TargetUnreachable).await;
                counter!("referee_dispatch_total", "ext_id" => ext_id_str, "result" => "closed").increment(1);
                Err(KernelError::TargetUnreachable)
            }
        }
    }
}
```
### 2.2 扩展执行层埋点 (`kernel/supervisor.rs`)
在 `run_inner_loop` 中，为每条消息的处理建立独立 Span，确保 `handle` 中的日志可以通过 `trace_id` 与 `dispatch` 阶段串联。`catch_unwind` 与 `instrument` 顺序保证 Panic 发生时 Span 也能被正确关闭。
```rust
use tracing::{info_span, Instrument};
use std::time::Instant;
use metrics::{histogram, counter};
impl ExtensionRuntime {
    async fn run_inner_loop(ext: &Box<dyn Extension>, rx: &mut PriorityReceiver, shutdown_rx: ShutdownRx) -> InnerOutcome {
        loop {
            tokio::select! {
                _ = shutdown_rx.wait() => return InnerOutcome::Shutdown,
                
                res = rx.recv() => {
                    match res {
                        Some(ctx) => {
                            // 构造处理 Span，通过 trace_id 关联上游日志
                            let span = info_span!(
                                "extension_handle",
                                trace_id = %ctx.envelope.trace_id,
                                correlation_id = %ctx.envelope.correlation_id,
                                ext_id = %ext.id()
                            );
                            
                            let start = Instant::now();
                            
                            // 顺序：先 catch_unwind，再 instrument
                            // 保证 Panic 时 catch_unwind 捕获，同时 instrument 能妥善关闭 Span
                            let fut = std::panic::AssertUnwindSafe(ext.handle(ctx));
                            let outcome = fut.catch_unwind().instrument(span).await;
                            
                            let elapsed = start.elapsed().as_secs_f64();
                            let status = if outcome.is_ok() { "ok" } else { "panic" };
                            
                            histogram!("referee_handle_duration_seconds", 
                                "ext_id" => ext.id().to_string(), 
                                "outcome" => status
                            ).record(elapsed);
                            
                            if outcome.is_err() {
                                // 记录 Panic 事件
                                counter!("referee_extension_panics_total", "ext_id" => ext.id().to_string()).increment(1);
                                return InnerOutcome::Crashed;
                            }
                        }
                        None => return InnerOutcome::NormalExit,
                    }
                }
            }
        }
    }
}
```

## 3. 核心指标埋点与原子性保障
**设计原理**：在 `PrioritySender` 和 `PriorityReceiver` 间共享 `Arc<AtomicUsize>` 计数器。利用 `Relaxed` 内存序实现无锁高性能计数，虽有极短暂采样延迟，但在监控可容忍范围内，完美适配高并发场景。
### 3.1 优先级路由埋点 (`kernel/priority.rs`)
```rust
use tokio::sync::mpsc;
use std::sync::Arc;
use std::sync::atomic::{AtomicUsize, Ordering};
use metrics::gauge;
use crate::common::envelope::Envelope;
use crate::extension::context::MessageContext;
use crate::extension::CapabilityId;
pub struct PrioritySender {
    high: mpsc::Sender<MessageContext>,
    norm: mpsc::Sender<MessageContext>,
    low: mpsc::Sender<MessageContext>,
    depth: Arc<AtomicUsize>,
    ext_id: CapabilityId,
}
pub struct PriorityReceiver {
    high: mpsc::Receiver<MessageContext>,
    norm: mpsc::Receiver<MessageContext>,
    low: mpsc::Receiver<MessageContext>,
    // Receiver 同样持有 depth 的 Arc 引用
    depth: Arc<AtomicUsize>,
    ext_id: CapabilityId,
}
impl PrioritySender {
    pub fn new(queue_size: usize, ext_id: CapabilityId) -> (PrioritySender, PriorityReceiver) {
        let (htx, hrx) = mpsc::channel(queue_size);
        let (ntx, nrx) = mpsc::channel(queue_size);
        let (ltx, lrx) = mpsc::channel(queue_size);
        let depth = Arc::new(AtomicUsize::new(0));
        
        (PrioritySender { high: htx, norm: ntx, low: ltx, depth: depth.clone(), ext_id }, 
         PriorityReceiver { high: hrx, norm: nrx, low: lrx, depth, ext_id })
    }
    pub fn try_send(&self, ctx: MessageContext) -> Result<(), mpsc::TrySendError<MessageContext>> {
        let res = match ctx.envelope.priority {
            0..=49 => self.high.try_send(ctx),
            50..=149 => self.norm.try_send(ctx),
            _ => self.low.try_send(ctx),
        };
        
        if res.is_ok() {
            let current = self.depth.fetch_add(1, Ordering::Relaxed) + 1;
            gauge!("referee_queue_depth", "ext_id" => self.ext_id.to_string()).set(current as f64);
        }
        res
    }
}
impl PriorityReceiver {
    pub async fn recv(&mut self) -> Option<MessageContext> {
        loop {
            if let Ok(ctx) = self.high.try_recv() { 
                self.update_depth();
                return Some(ctx); 
            }
            if let Ok(ctx) = self.norm.try_recv() { 
                self.update_depth();
                return Some(ctx); 
            }
            if let Ok(ctx) = self.low.try_recv() { 
                self.update_depth();
                return Some(ctx); 
            }
            
            tokio::select! {
                biased;
                Some(ctx) = self.high.recv() => {
                    self.update_depth();
                    return Some(ctx);
                }
                Some(ctx) = self.norm.recv() => {
                    self.update_depth();
                    return Some(ctx);
                }
                Some(ctx) = self.low.recv() => {
                    self.update_depth();
                    return Some(ctx);
                }
                else => return None,
            }
        }
    }
    
    #[inline]
    fn update_depth(&self) {
        let current = self.depth.fetch_sub(1, Ordering::Relaxed) - 1;
        gauge!("referee_queue_depth", "ext_id" => self.ext_id.to_string()).set(current as f64);
    }
}
```

## 4. 测试矩阵与初始化样板
在测试模块中提供全局导出器初始化样板，确保测试用例可输出结构化日志并验证可观测性闭环。
### 4.1 测试初始化样板
```rust
#[cfg(test)]
mod tests {
    use tracing_subscriber::fmt;
    
    fn init_observability() {
        // try_init 防止多测试并行时重复初始化 panic
        let _ = fmt()
            .with_max_level(tracing::Level::INFO)
            .with_target(false)
            .try_init();
    }
    
    // 后续所有测试用例起始处调用 init_observability()
}
```
### 4.2 验证用例
1. **Span 穿透与关联验证**：调用 `init_observability()` 后 `invoke` 一个扩展，捕获 stdout 输出。验证包含 `kernel_dispatch` 与 `extension_handle` 的日志行均带有相同的 `trace_id`。
2. **队列深度指标验证**：向扩展 `emit` 5 条消息（扩展不消费），通过 `metrics` recorder 捕获，验证 `referee_queue_depth` 指标值为 5；启动消费后，验证指标回落至 0。
3. **处理延迟与 Panic 指标验证**：构造一个 sleep 100ms 的扩展，验证 `referee_handle_duration_seconds` 记录值在 0.1s 附近且 `outcome=ok`；构造一个主动 `panic!` 的扩展，验证 `outcome=panic` 的耗时被记录，且 `referee_extension_panics_total` 计数器递增。
4. **路由失败指标验证**：向已满的队列发消息，验证 `referee_dispatch_total` 中 `result=full` 的计数器递增。
